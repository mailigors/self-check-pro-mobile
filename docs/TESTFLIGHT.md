## Проверенный блокер API

9 октября 2026 года сервер `188.242.121.224` предоставлял TLS-сертификат только для `selfcheck.pro` и `www.selfcheck.pro`. HTTPS по IP не проходит проверку имени сертификата. В приложении проверка сертификатов сохранена.

Запрос `https://selfcheck.pro/api/v1/users/me` с принудительным соединением к `188.242.121.224` возвращал ожидаемый HTTP 401 без авторизации. Обычное обращение к домену в тот же момент шло на другой IP и возвращало 404. Для работы приложения с заданным адресом требуется действительный сертификат для IP либо согласованное изменение адреса и DNS.

После сообщения пользователя об ошибке установленного приложения проверки повторены: сертификат для IP по-прежнему не подходит, домен разрешается в `139.100.225.163` и API возвращает 404. По запросу «правь» адрес приложения изменён на домен. Для работы новой сборки нужно направить DNS `selfcheck.pro` на `188.242.121.224`. Проверка сертификатов сохранена.

## Прямое подключение — сборка 3

Пользователь требует подключение к `188.242.121.224` без изменений DNS. Для native-платформ настроен Dio IOHttpClientAdapter: TCP-сокет создаётся напрямую к IP, затем SecureSocket выполняет TLS с именем `selfcheck.pro`, соответствующим сертификату сервера. HTTP Host также остаётся `selfcheck.pro`. Проверка сертификатов не отключается. Запросы к другим хостам не перенаправляются на IP бекенда. В браузере используется обычный транспорт, так как браузер не предоставляет управление DNS/сокетами.

Проверка `dart run tool/check_backend_transport.dart` выполнила запрос тем же транспортом без авторизации: HTTP 401, TLS успешно проверен. Контрольный запрос HTTPS по IP с несовпадающим именем сертификата отклонён с `CERTIFICATE_VERIFY_FAILED`. Вход и действия с чек-листами на физическом iPhone пока не проверены.
