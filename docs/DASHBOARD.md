# Дашборд мобильного приложения

После входа и восстановления сохранённой сессии приложение открывает `/` — дашборд. Список чек-листов доступен по `/checklists`, профиль — по `/profile`.

Экран следует композиции https://bkx4pgq2orzl4.kimi.page/: показатели, динамика оценок, объекты и проверки, требующие внимания. Неделя, месяц и квартал означают последние 7, 30 и 90 календарных дней, включая сегодня. Для квартала динамика группируется по неделям, для остальных периодов — по дням.

## Подключение API

Используется общий `ApiClient` приложения с Bearer-токеном и обновлением токенов. Контракты взяты из `self-check-pro-fe/frontend/src/services/api.js`, `utils/analyticsParams.js` и `frontend/docs/api.json`.

| Блок | GET endpoint | Поля |
| --- | --- | --- |
| В работе, завершено, средняя оценка | `/reports/checklists/summary` | `inWorkCount`, `completedCount`, `controlResult` |
| Проверок за период, график | `/reports/checklists/dynamics` | сумма `createdCount`, `period`, `controlResult` |
| По объектам | `/dashboard/objects-rating` | `name`, `completedChecklists`, `controlResult`, `controlResultDynamic` |
| Требуют внимания | `/dashboard/deviations` | `content[].checklistId`, `templateName`, `controlObjectName`, `deviationReason` |

Все запросы передают `fromDate` и `toDate` в формате `YYYY-MM-DD`. Динамика дополнительно передаёт `groupBy=DAY` или `WEEK`. Показатели, динамика и рейтинг объектов передают `inspectorIds=ID` авторизованного пользователя. Отклонения не поддерживают серверный фильтр инспектора: страницы по 100 записей с `sort=startAt,desc` просматриваются до десяти записей с нужным `inspectorId` либо конца списка. Записи других пользователей не отображаются.

Для обычных ролей `organisationId` не передаётся: область данных определяет сервер. Системный администратор сначала выбирает организацию из `/organizations`, после чего запросы передают `organisationId`, как web-версия.

## Семантика данных

Счётчики в сводке и рейтинги объектов являются снимком на `toDate`. `controlResult` — оценка контроля; `averageCompletion` — доля завершения и не используется как оценка. Отсутствующая оценка отображается как «—».

В прототипе «Требуют внимания» содержит низкие оценки. Доступный API `/dashboard/deviations` возвращает отклонения по срокам (`NOT_COMPLETED`, `LATE_COMPLETION`), поэтому текущий экран явно показывает причины нарушения сроков вместо вымышленных низких оценок.

Каждый блок имеет загрузку, состояние без данных, ошибку и повторный запрос. Данные автоматически обновляются при повторном входе в раздел дашборда; выбранный период сохраняется. Обновление также доступно через кнопку и жест потягивания вниз. Нажатие «В работе» открывает `/checklists?status=IN_WORK`; нажатие отклонения открывает существующий экран заполнения проверки, возврат обновляет дашборд.

## Проверка

`flutter analyze --no-pub` и `flutter test --no-pub`. Контракт API проверяется через тестовый HTTP-адаптер; сценарии интерфейса используют изолированные данные. `tool/design_preview.dart` включает дашборд с этими же данными; производственный `lib/main.dart` использует API.
