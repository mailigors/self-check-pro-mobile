# Дашборд мобильного приложения

После входа и восстановления сохранённой сессии приложение открывает `/` — дашборд. Список чек-листов доступен по `/checklists`, профиль — по `/profile`.

Экран следует композиции https://bkx4pgq2orzl4.kimi.page/: показатели, динамика оценок, объекты и проверки, требующие внимания. Неделя, месяц и квартал означают последние 7, 30 и 90 календарных дней, включая сегодня. Для квартала динамика группируется по неделям, для остальных периодов — по дням.

## Подключение API

Используется общий `ApiClient` приложения с Bearer-токеном и обновлением токенов. Контракты взяты из `self-check-pro-fe/frontend/src/services/api.js`, `utils/analyticsParams.js` и `frontend/docs/api.json`.

| Блок | GET endpoint | Поля |
| --- | --- | --- |
| В работе, завершено | `/checklists?user_id=ID&status=IN_WORK/COMPLETED` | `totalElements`, при отсутствии — подсчёт всех страниц |
| Средняя оценка | `/reports/checklists/summary` | `controlResult` |
| Проверок за период, график | `/reports/checklists/dynamics` | сумма `createdCount`, `period`, `controlResult` |
| По объектам | `/dashboard/objects-rating` | `name`, `completedChecklists`, `controlResult`, `controlResultDynamic` |
| Требуют внимания | `/dashboard/deviations` | `content[].checklistId`, `templateName`, `controlObjectName`, `deviationReason` |

Все запросы передают `fromDate` и `toDate` в формате `YYYY-MM-DD`. Динамика дополнительно передаёт `groupBy=DAY` или `WEEK`. Показатели, динамика и рейтинг объектов передают `inspectorIds=ID` авторизованного пользователя. Отклонения не поддерживают серверный фильтр инспектора: страницы по 100 записей с `sort=startAt,desc` просматриваются до конца списка. Сохраняются записи с нужным `inspectorId`, чей `checklistId` присутствует в доступном пользователю списке `/checklists?user_id=ID`; повторы удаляются. Сначала показаны три записи, кнопка раскрывает полный список. Блок расположен перед показателями, чтобы быть видимым сразу.

Для обычных ролей `organisationId` не передаётся: область данных определяет сервер. Системный администратор сначала выбирает организацию из `/organizations`, после чего запросы передают `organisationId`, как web-версия.

## Семантика данных

Счётчики «В работе» и «Завершено» соответствуют текущему доступному пользователю списку и не зависят от выбранного периода. Рейтинг объектов и средняя оценка являются снимком на `toDate`. `controlResult` — оценка контроля; `averageCompletion` — доля завершения и не используется как оценка. Отсутствующая оценка отображается как «—».

В прототипе «Требуют внимания» содержит низкие оценки. Доступный API `/dashboard/deviations` возвращает отклонения по срокам (`NOT_COMPLETED`, `LATE_COMPLETION`), поэтому текущий экран явно показывает причины нарушения сроков вместо вымышленных низких оценок.

Каждый блок имеет загрузку, состояние без данных, ошибку и повторный запрос. Данные сохраняются в памяти в пределах авторизованной сессии и автоматически обновляются в фоне при повторном входе в раздел; предыдущие значения остаются видимыми во время запроса. Смена сессии сбрасывает кеш. Выбранный период сохраняется. Обновление также доступно через кнопку и жест потягивания вниз. Нажатие «В работе» открывает `/checklists?status=IN_WORK`; «Завершено» и «Средняя оценка» открывают завершённые проверки, «Проверок за период» — список с фильтрами `created_at_from/created_at_to`, объект — завершённые проверки данного объекта. Активные фильтры даты/объекта показаны отдельной меткой и снимаются её кнопкой. Нажатие отклонения открывает существующий экран заполнения проверки, возврат обновляет дашборд.

## Проверка

`flutter analyze --no-pub` и `flutter test --no-pub`. Контракт API проверяется через тестовый HTTP-адаптер; сценарии интерфейса используют изолированные данные. `tool/design_preview.dart` включает дашборд с этими же данными; производственный `lib/main.dart` использует API.
